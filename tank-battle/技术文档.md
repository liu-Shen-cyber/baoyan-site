# 坦克大战（Cyber Tank Battle）技术文档

> 面向单独开发者的完整实现说明书。本文档用于指导从零实现一款**科技风格、玩法多样、含大 Boss** 的坦克大战网页小游戏。
> 开发者只需按照本文档的模块划分、规则定义与验收标准逐步编码即可，无需额外设计。

---

## 1. 项目概述

### 1.1 定位
一款运行在浏览器中的单机坦克大战游戏，玩家操控己方坦克，消灭敌方坦克与最终 Boss，守护己方基地。

### 1.2 目标体验
- 画面**科技感/赛博朋克风**：霓虹描边、发光炮口、粒子爆炸、雷达界面。
- 玩法**多样**：多种敌方坦克类型、道具系统、波次进攻、Boss 战。
- 操作**流畅**：即时响应、清晰的碰撞与命中反馈。

### 1.3 基本要求（必须满足）
1. **可玩性**：玩家可操控坦克移动、发射炮弹。
2. **碰撞与判定**：存在敌方坦克或障碍物，具备基本碰撞检测与胜负判定。
3. **界面与反馈**：游戏界面清晰，操作反馈明确（命中、爆炸、加分、胜负提示）。

## 2. 技术栈

| 项 | 选型 | 说明 |
|---|---|---|
| 语言 | 原生 HTML + CSS + JavaScript（ES6+） | 零依赖，单文件可运行，便于部署与调试 |
| 渲染 | HTML5 `<canvas>` 2D | 高性能绘制游戏画面 |
| 样式 | CSS3 + 变量 | 科技感 UI、响应式布局 |
| 音频 | Web Audio API | 程序化生成音效，无需外部音频文件 |
| 构建 | 无 | 纯静态，直接双击 `index.html` 或本地静态服务运行 |

> **交付形式：单文件** `index.html`，内联全部 CSS 与 JS，双击即可游玩，便于部署与分享。

## 4. 核心玩法与规则

### 4.1 玩家操作（键盘）
| 按键 | 功能 |
|---|---|
| `W` / `↑` | 坦克向上移动 |
| `S` / `↓` | 坦克向下移动 |
| `A` / `←` | 坦克向左移动 |
| `D` / `→` | 坦克向右移动 |
| `空格` / `J` | 发射炮弹 |
| `P` | 暂停 / 继续 |
| `Enter` | 开始 / 重新开始 |

- 坦克**只能朝当前朝向移动**，转向后再移动。
- 支持**多键同时按下**（如移动中斜向转向 + 持续射击）。

### 4.1.1 触屏操作（移动端）
- 屏幕左侧**虚拟摇杆**：拖动控制坦克移动与转向（摇杆角度即坦克朝向）。
- 屏幕右侧**射击按钮**：长按持续射击。
- 缩放手势禁用，避免误触发页面缩放。
- 仅当设备为触摸屏时显示摇杆与按钮（PC 端隐藏）。

### 4.2 游戏对象
| 对象 | 说明 |
|---|---|
| 玩家坦克 | 生命值、装甲、火力等级 |
| 敌方坦克 | 多种类型，不同速度/血量/火力 |
| 基地 | 我方需守护的终点，被摧毁则失败 |
| 障碍物 | 砖墙（可摧毁）、钢墙（不可摧毁）、水域（不可通行）、草丛（遮挡） |
| 道具 | 定时刷新，拾取后增强能力 |
| 炮弹 | 玩家/敌方发射，命中造成伤害 |
| Boss | 关卡最终目标，血厚、多弹道、召唤小兵 |

### 4.3 胜负判定
- **胜利**：消灭当前波次所有敌方坦克 + 击败 Boss。
- **失败**：玩家坦克生命归零，或基地被摧毁。

### 4.4 游戏流程
```
开始界面 → 进入关卡 → 波次 1 → 波次 2 → … → 每 N 波刷新 Boss 波 → 通关最终波 → 胜利结算
                                     ↘ 玩家死亡/基地被毁 → 失败结算
```

## 5. 玩法多样设计（敌人与波次）

### 5.1 敌方坦克类型
| 类型 | 速度 | 生命 | 特性 |
|---|---|---|---|
| 侦察型 | 快 | 1 | 伤害低，移动灵活 |
| 普通型 | 中 | 2 | 均衡 |
| 重装型 | 慢 | 4 | 高血量，移动慢 |
| 精英型 | 中 | 3 | 命中率高，可发射双发 |
| Boss | 慢 | 20+ | 多弹道、护盾、召唤小兵 |

### 5.2 波次系统
- 每波按预设**编队表**生成敌人（如 3 侦察 + 3 普通 → 逐渐增加重装/精英）。
- 波次之间短暂倒计时，显示下一波预告。

### 5.3 Boss 刷新机制（每 N 波刷新一次）
- **Boss 每隔固定波数刷新**（如每 3 波出现 1 次，即第 3、6、9… 波为 Boss 波）。
- Boss 波：先刷出少量杂兵，再登场 Boss。
- 击败 Boss 获得大量奖励分，并自动进入下一波，Boss 在后续每隔 N 波再次刷新挑战更高难度。
- 通关最终波（Boss 波）后进入胜利结算。

### 5.4 道具系统（定时在随机空地刷新）
| 道具 | 效果 |
|---|---|
| ⚡ 火力提升 | 子弹伤害提升 |
| ❄ 减速 | 短暂减慢全场敌人速度 |
| 🛡 护盾 | 玩家获得临时无敌 |
| ❤ 生命 | 恢复玩家生命 |
| 💣 炸弹 | 清空当前屏幕内所有普通敌人 |

## 6. 碰撞检测

采用 **AABB（轴对齐包围盒）** 检测，简单高效，适合本游戏。

### 6.1 检测对象
- 坦克 vs 障碍物（砖墙/钢墙/水域）
- 坦克 vs 地图边界
- 炮弹 vs 障碍物（砖墙可被摧毁、钢墙反弹或消失）
- 炮弹 vs 敌方坦克 / 玩家坦克
- 炮弹 vs 基地
- 坦克 vs 坦克（不可重叠）

### 6.2 实现建议
- 统一提供 `rectsOverlap(a, b)` 函数。
- 移动时先按新坐标做预测碰撞，若重叠则**回退并阻止移动**。
- 炮弹命中后立即销毁，并触发爆炸粒子。

## 7. 界面（UI/UX）设计

### 7.1 布局
- 顶部 **HUD**：生命值、当前波次、剩余敌人、得分、暂停按钮。
- 中部 **游戏画布**（Canvas）。
- 移动端：左下 **虚拟摇杆**、右下 **射击按钮**（仅触摸屏显示）。
- 结束/开始 **弹窗**：半透明遮罩 + 科技描边面板。

### 7.2 反馈要求（务必实现）
- 命中敌人：粒子爆炸 + 音效 + 得分飘字。
- 玩家受伤：屏幕红闪 + 音效。
- 拾取道具：提示文字 + 音效。
- 胜利/失败：弹窗 + 结算得分。

### 7.3 科技风格视觉
- 主色调：深蓝/黑背景 + **霓虹青（#00ffff）**、品红（#ff00ff）描边。
- 元素带**发光**（`box-shadow` / `canvas` 发光描边）。
- 加粗"程序绘制"：所有坦克、Boss、道具、障碍物均用 **Canvas 几何图形绘制**（矩形车身 + 炮管 + 高光线），不依赖外部图片素材。
- 背景网格 + 扫描线，营造雷达/赛博感。

## 8. 音效（Web Audio API）

程序化生成，避免外部文件：
- 射击：短促高频音。
- 爆炸：低频噪声衰减。
- 拾取：上行短音。
- 受伤：低沉警示音。
- 胜利/失败：旋律。

## 9. 技术架构与状态管理

### 9.1 游戏循环
使用 `requestAnimationFrame`，固定时间步（`deltaTime`）驱动更新与绘制。

### 9.2 状态机
```
MENU(开始) → PLAYING(运行中) → PAUSED(暂停)
                      ↓
              WIN / LOSE(结算)
```

### 9.3 核心数据结构
```js
// 示例：游戏主状态对象
const gameState = {
  status: 'PLAYING',        // MENU | PLAYING | PAUSED | WIN | LOSE
  score: 0,
  wave: 1,
  player: { x, y, hp, dir, fireLevel, shield },
  enemies: [],              // 敌方坦克数组
  bullets: [],              // 炮弹数组
  bulletsE: [],             // 敌方炮弹
  particles: [],            // 粒子特效
  items: [],                // 道具数组
  map: [],                  // 二维地图（障碍物布局）
  keys: {},                 // 按键状态
};
```

## 10. 代码结构（单文件内 JS 模块划分）

> 所有模块均写在 `index.html` 的 `<script>` 中，以注释分割，逻辑与上述模块一一对应。

| 模块 | 职责 |
|---|---|
| `init()` | 初始化画布、加载地图、重置状态 |
| `Map` | 地图生成与障碍物管理 |
| `Tank` | 坦克基类（移动、转向、绘制） |
| `PlayerTank` | 玩家坦克逻辑与输入 |
| `EnemyTank` | 敌方 AI（寻路、射击、类型） |
| `Boss` | Boss 行为（多弹道、护盾、召唤） |
| `Bullet` | 炮弹逻辑与碰撞 |
| `Item` | 道具生成与拾取 |
| `Particle` | 爆炸/特效粒子系统 |
| `Collision` | AABB 碰撞检测集合 |
| `EnemyAI` | 敌人移动与射击决策 |
| `WaveSystem` | 波次生成与调度（含 Boss 波，每 N 波刷新） |
| `TouchInput` | 触屏虚拟摇杆 + 射击按钮输入处理 |
| `AudioSystem` | Web Audio 音效 |
| `HUD` | 顶部信息与弹窗渲染 |
| `GameLoop` | 主循环与状态机 |

## 11. 验收标准（QA Checklist）

必须全部通过：
- [ ] 玩家可用键盘移动坦克并发射炮弹。
- [ ] 移动端可用虚拟摇杆移动转向、射击按钮发射。
- [ ] 存在敌方坦克与障碍物，碰撞检测正确（坦克被阻挡、炮弹命中销毁）。
- [ ] 有胜负判定：通关最终波胜利；玩家死亡或基地被毁失败。
- [ ] Boss 每隔固定波数（如每 3 波）刷新一次。
- [ ] 界面清晰，命中/爆炸/得分/胜负均有明确反馈。
- [ ] 至少 3 种敌方类型 + 1 个 Boss + 道具系统。
- [ ] 全部图形为 Canvas 程序绘制，无外部图片素材。
- [ ] 科技风格视觉统一，响应式适配 PC 与移动端。
- [ ] 无控制台报错，`requestAnimationFrame` 循环稳定。
